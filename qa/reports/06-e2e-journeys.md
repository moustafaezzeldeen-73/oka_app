# 06 — E2E shopper journeys (runtime)

**Scope.** Every shopper journey of the test theme "OKA App Theme (test — unpublished)" driven in a real browser (Chromium 141 via Playwright 1.56.1) against the local storefront harness (`qa/harness/server.mjs`, port 9410, logs in `qa/harness/out-e2e/`). Devices: iPhone 13 and Pixel 7 for every group, Desktop 1440 for the main flows (age gate, menu, home, collections/search, PDP). The Desktop pass of the cart group was lost when another agent killed the shared harness server; the cart was run on iPhone 13 + Pixel 7 only. Languages: Arabic (RTL) and English. Guest and signed-in (fake fixture customer). External services (orders API / J&T tracking on the run.app URL, Nominatim, model-viewer CDN) were always mocked by the harness. Nothing reached a live system; no Shopify mutation was made.

**Method.** Seven runnable scripts in `qa/tests/e2e/` (shared helpers in `lib.mjs`). Each records one row per scenario × context into `qa/tests/e2e/results/<script>.json`. `node qa/tests/e2e/checklist.mjs` turns those rows into the checklist at the end of this report. Screenshots: `qa/reports/screenshots/e2e/`. For each step the scripts collect console errors, uncaught page errors, failed requests and HTTP ≥400, and they read `checkouts.jsonl`, `forms.jsonl` and `external-calls.jsonl` from the out dir.

```
PORT=9410 QA_OUT_DIR=qa/harness/out-e2e node qa/harness/server.mjs &
node qa/tests/e2e/01-agegate-menu.mjs        # age gate, side menu, language
node qa/tests/e2e/02-home.mjs                # home feed, offers, cards, compare, ribbon
node qa/tests/e2e/03-collections-search.mjs  # 14 collections, sort/filter, 16 search queries
node qa/tests/e2e/04-pdp.mjs                 # 10 PDPs, qty, add, F-05, share, wishlist, reel, AR
node qa/tests/e2e/05-cart.mjs                # cart, codes, zone fees, 299/300/301, checkout hand-off
node qa/tests/e2e/06-account-orders.mjs      # orders, tracking/edit/cancel mocks, addresses, loyalty…
node qa/tests/e2e/07-guest-misc-resilience.mjs  # guest orders, 404/policies, multi-tab, back/fwd, offline
node qa/tests/e2e/checklist.mjs              # regenerates the scenario checklist
E2E_DEVICES='iPhone 13' node qa/tests/e2e/05-cart.mjs   # optional: restrict devices
```

**Covered.** Age gate (first visit, accept, decline, reload, 9 deep links, cleared and blocked storage). Search: 16 queries (Arabic folding, typos, empty, no-result, `<script>`, attribute break-out, 600 chars, Arabic digits) and the chips. PDP: 10 products (3D, video, sold out, compare-at, no `description_ar`, story families), quantity, Add, double Add (F-05), share, wishlist, reel sound, `?variant=`, COM-07, related rail, Back. AR screen with the camera granted, denied and absent, the no-model page, and the PDP AR section auto camera (F-03/F-10). Cart: empty state, multi-line, −/+, ✕, swipe delete/save, Change sheet, fast taps with and without latency (F-02), 422 alert, 99 cap, 8 codes, QAMIN300 at 299/300, COM-06, code persistence, 299/300/301 tiers, guest vs each of the 3 customer addresses (cart + checkout-review), "tong free", checkout hand-off (`checkouts.jsonl`), Back from checkout, checkout-review guest/customer, sign-in hand-off, cart permalink. Misc: 404 ×3, password, gift card, 5 policies + `/ar/` policies, multi-tab (COM-09), bfcache badge, Back/Forward through the funnel, reload mid-flow, and offline for add, steppers, checkout, tracking and codes.

**Not covered / limits.** Real Shopify checkout (stub only: shipping rates, COD fee, store credit and the checkout pixel never run). Real video playback (empty mp4 files). Real AR (Scene Viewer, Quick Look, WebXR). Real network latency (simulated only for F-02). WebKit/Safari: the iPhone 13 profile runs in Chromium. Real new-customer-accounts sign-in. The real orders-API contract: mock payload shapes are inferred from the theme. bfcache: Playwright's Chromium did not restore pages from bfcache, so the "spinner after Back" half of F-16 could not be reproduced. Live data drift after 2026-10-14.

**Theme version.** Groups 01–03 ran on the theme as of 2026-10-14. Groups 04–07 were re-run sequentially on the 2026-10-19 update of `theme/` (newer product-page commit); 04's verdicts were identical before and after the update.

### E2E-01 · Medium · Age gate has no decline path and is not modal
- **Refs:** `theme/assets/oka.js:655-670` (`ageGate()`). The overlay is a plain `div.overlay.age-gate` with only `[data-yes]` and `[data-lang]` buttons. It has no `role="dialog"`/`aria-modal`, no focus trap and no Escape/decline handling.
- **Repro:** fresh context (`ageConfirmed:false`) → `/` → press Tab six times.
- **Expected:** a minor can answer "No" and leave (or see a "you must be 18+" screen). Focus stays inside the gate, and screen readers announce it as a dialog.
- **Actual:** the buttons are only `["Yes, I’m 18+","العربية"]` on all 6 device/language contexts. Escape leaves the gate up, so there is no way out except "Yes". Focus escaped the gate on 6/6 Tab presses on iPhone 13, Pixel 7 and Desktop 1440. On desktop the overlay covers only the 430 px column. The gate is client-side only (product HTML is served and readable without JS), and the `/password` and `/checkout` pages have no gate (expected for checkout).
- **Evidence:** `results/01-agegate-menu.json` AG-2/AG-3. Screenshots `screenshots/e2e/agegate-first-*.png`.
- **Fix:** add a "No" button that shows an "adults only" screen (and doesn't store `oka.age`). Give the card `role="dialog" aria-modal="true" aria-labelledby`, set `inert` on `#app > :not(.age-gate)` while it is open, and focus the Yes button.

### E2E-02 · Low · Cancel state not kept across reload
- **Refs:** `oka-screens.js:1714` reads `O.store.get('oka.cancelled', {})` and `:2411` deletes it on sign-out, but no code ever writes it. `markCancelled()` (`:1766`) only changes the DOM.
- **Repro:** signed-in → `/pages/orders?order=%239000106` → Cancel Order → Cancel order (API ok, banner shown) → reload.
- **Expected:** per the code comment, "an order cancelled from here shows as cancelled at once, even while Shopify's background cancel job hasn't reached it yet".
- **Actual:** after reload the banner is gone and `data-cancelled="false"`. Edit and Cancel are active again; the API answers "already cancelled" on a second try. `oka.cancelled` is `null`. In the harness the fixture never changes, so this shows the worst case of the lag window.
- **Evidence:** `results/06-account-orders.json` OR-7 (all contexts), `screenshots/e2e/order-cancelled-*.png`.
- **Fix:** in the cancel `onPress` success path, add `O.store.set('oka.cancelled', { ...O.store.get('oka.cancelled', {}), [name]: Date.now() })`, and expire entries after about a day.

### E2E-03 · Low · Tracking errors are invisible
- **Refs:** `oka-screens.js:1835` (`loadJt`: `catch (e) { return; }`) and `track()` at `:1410`, which does show an error on the standalone track page.
- **Repro:** signed-in, `qa_mock=track_delivery:error500,success` (also 401, timeout, malformed, rpc-error, tool-error, cors) → `/pages/orders?order=%239000103`.
- **Actual:** the result is identical to the `empty` mode. The detail says "No updates for this order yet", the steps stay at the Liquid step, and the list chips fall back from "Out for delivery/Delivered" to "Preparing to ship/Shipped". No retry hint is shown. `/pages/track` does say "We couldn’t reach J&T just now".
- **Fix:** on catch, add the `ship-err` note already used for the order-service path (`:1871`).

### E2E-04 · Low · Code with spaces shows "Apply" although applied
- **Refs:** `oka-screens.js:826` compares `codeState.code === code`. `codeState.code` is trimmed (`c`) while `code` keeps the spaces.
- **Repro:** cart 300 EGP → type ` QA10 ` → Apply.
- **Actual:** the discount is applied (total 270), but the button reads "فعّل"/"Apply" instead of "اتفعّل"/"Applied" (DC-1).
- **Fix:** compare against `code.trim()`, or write the trimmed code back into `code`.

### E2E-05 · Low · Filters leak across collections
- **Refs:** `oka-screens.js:385-416`, where `oka.sort`/`oka.filters` are single sessionStorage keys shared by every collection.
- **Repro:** `/collections/oka-parts` → In stock + On sale (empty state) → open `/collections/oka-cobra`.
- **Actual:** both chips are still on and only 1 of 3 Cobra products shows. CL-4 shows this on every context.
- **Fix:** key the state by collection handle (`oka.filters:<handle>`), or reset it when the handle changes.

### E2E-06 · Low · Desktop menu doesn't close on outside click
- **Refs:** `layout/theme.liquid:242` — `.menu-scrim` sits inside `#app` (430 px wide on desktop).
- **Repro:** Desktop 1440 → ☰ → click at x=1420.
- **Actual:** the menu stays open, and the ☰ is covered by the scrim (MN-3b). Escape, ✕ and the scrim inside the column work.
- **Fix:** make the scrim `position: fixed; inset: 0`, or close on `pointerdown` outside `#side-menu`.

### E2E-07 · Info · Bundle offer 1 and the 300 tier
Offer 1 = cloud hookah 169 + 2 bowls 49+49 + tongs 31 = 298. "tong free" then makes it 267 + 60 shipping = 327. Offer 2 = 467 → 395 (Valentines) + 36 = 431 (HM-6). Seen on every context. Not a bug per COM-15, but the store's flagship offer sits 2 EGP under the tier before discount: a "+1 bowl" nudge or pricing it at ≥300 after discount would save the shopper 24 EGP.

### E2E-08 · Info · Rec sheet after Add
`oka-screens.js:3160-3215`. The first Add of a product (once per product per session, at most every 45 s) opens a bottom sheet with "Keep shopping / View cart" over the grid or PDP. It works: Add from the sheet adds and `data-close` closes it. It intercepts the next tap, though, so a shopper adding two things quickly loses the second tap. Tests had to dismiss it (`lib.mjs: dismissRecSheet`).

### E2E-09 · Info · English item titles in the Arabic edit sheet
With the harness mock, `customer_get_order` items carry Shopify's English `title`, which the sheet prints as is. Items added from the catalogue picker show Arabic. If the real API returns English line-item titles, map them by `variantId` through the catalogue (`O.ptitle`).

### E2E-10 · Info · Sign-in URL locale
`CFG.routes.login` = `routes.storefront_login_url`, which carries `locale=en` (Shopify's primary-locale request on `/`). `return_to` is the current page and the theme also stores `oka.afterSignIn`. Arabic UI users land on an English hosted sign-in. Needs a live check together with SI-05.

### E2E-11 · Info · Harness title reflection
`/search?q=</title><script>…` puts the raw query into `<title>` in the harness only (`qa/harness/server.mjs:246`). Client-side, the query is always escaped: no script ran, and no `<img>` or `<script>` was injected in 16 queries × 6 contexts (SR-1).

## Scenario notes worth knowing (PASS, but informative)
- Bundle offers are atomic. With a sold-out variant injected, nothing is added and a toast explains (HM-8). A double tap adds once (HM-7). Side-offer taps only centre the card (HM-5).
- Search folds ة/ه, ى/ي and Arabic-Indic digits: "شيشه" and "شيشة" both return 18. Typos ("hokah", "شيشا") return 0, with no fuzzy matching. A single letter "ب" returns 31 products, which is noisy.
- Collections paginate by 250, so `?page=2` is empty. A Shopify `?sort_by=price-ascending` deep link is ordered by the server, but the chip still reads "Featured" (CL-5).
- PDP `?variant=` ignores bogus or foreign ids and falls back to the product's variant (PD-9).
- The orders API received only the documented tools (`track_delivery`, `customer_get_order/quote/update/cancel`). No tool outside the theme's list was called.
- Checkout hand-off: `checkouts.jsonl` recorded the correct items, the applied code (`QA10` applicable), an empty note/attributes and the cart token. `oka.lastCheckout` was saved with the same token (CO-1).
- Offline Checkout navigates to Chrome's offline error page (OF-3). That is expected browser behaviour; the theme has no offline guard.
